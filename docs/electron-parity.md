# Electron ssdev-desktop → Tauri 能力差异审计

本表以旧项目 `/Users/yangl/IdeaProjects/ssdev-desktop/src/main/index.js` 及其 renderer 源码为行为证据。迁移目标是保留业务结果和运维能力，不复刻 Electron 的 Node 集成、任意脚本执行、宽松 CORS 或安全响应头删除等实现细节。

| 旧 Electron 能力 | Tauri 目标 | 状态与决策 |
| --- | --- | --- |
| 业务首页、多个业务窗口 | 发布方签名来源内的受控 WebView | 已实现；主入口、同源/授权来源子窗口、标题、显示器、结构化上下文和有界尺寸/坐标均可用；最多同时 16 个业务窗口 |
| `open-new-window` 的 `extras`/`urt` 全局变量注入 | `openWindow({ context })` | 已实现；上下文必须是最大 64 KiB 的 JSON 对象，并以只读 `ssdevDesktopContext` 暴露，不执行拼接 JavaScript |
| 多环境编辑、默认环境、`allowSwitch` | 控制台环境列表与受控切换 | 已实现；最多 32 个唯一环境，名称/URL 有界；保存或打开前必须通过本地校验和发布方签名来源策略 |
| 配置导入/导出 | 控制台用户选择文件后原子导入/导出 | 已实现；仅内置控制台可调用，导入只接受最大 1 MiB 的普通 JSON 文件，完整校验和签名来源授权通过后才替换活动配置 |
| 每窗口托盘、环境单选项 | 单实例托盘 + 本地控制台环境治理 | 已替代；保留默认入口、环境快捷切换、刷新、清理站点数据和退出；菜单只引用当前已保存环境，点击时重新核对切换开关和签名来源策略，避免多个托盘状态分叉 |
| 业务页动态设置托盘提示 | 固定产品身份 | 不迁移；远程页面不能伪装本地客户端身份或修改系统托盘文案 |
| 悬浮窗、关闭、处理结果回传 | 有界无边框悬浮窗 | 已实现；来源、尺寸、时长、上下文和返回值均有上限，悬浮页没有插件和通用桌面权限 |
| 区域截图、业务窗口反馈截图 | 本地确认的区域截图与聚焦窗口截图 | 已实现；原始屏幕数据不暴露给业务页，只把确认后的 PNG 通过事件交给调用窗口 |
| 清除缓存、强制刷新 | 控制台/托盘清理站点数据与刷新业务窗口 | 已实现 |
| 全局搜索、重置缩放、新建窗口快捷键 | 声明式有限动作快捷键 | 已实现；不恢复任意 `eval(snippet)`；`F5` 不再被操作系统级全局劫持 |
| `keymap.json` 任意 JavaScript | 固定 `DesktopAction` 枚举 | 已替代；只允许打开窗口、两类截图、重置缩放和查找，数量与快捷键文本有界 |
| `/sys.desktop.process.dic` + Shell 命令启动 | 签名进程策略 | 已替代；不执行服务器返回的路径，不经过 Shell，并验证固定可执行文件身份与参数 |
| `/sys.desktop.windowNum.dic` | 客户端固定窗口资源上限 | 已替代；业务服务不能动态扩大本地 WebView 资源边界 |
| 启动参数 SSO、灰度确认、查询串登录信息 | HTTPS-only 有界 SSO 流程 | 已替代；禁止重定向、URL 凭据和 HTTP，敏感启动参数不写日志，不再由业务页拼接任意登录脚本 |
| `localhost:45121/desktop/notice`、`/desktop/cache` | 默认无监听端口 | 有条件不迁移；只有关键流程 HAR 证明普通浏览器仍调用它们且调用方无法同步升级时，才设计独立、默认关闭的兼容适配器 |
| 复制 userData/localStorage 到新窗口 | 同一受控 WebView 会话 | 已替代；不复制任意磁盘目录，子窗口由桌面运行时管理同一应用会话 |
| 删除 `X-Frame-Options`、允许不安全内容 | 尊重服务端安全头和签名来源导航 | 不迁移；客户端不改写服务端点击劫持与内容隔离策略 |
| `nodeIntegration`、remote、禁用同源策略 | 窄 Tauri IPC ACL | 不迁移；远程业务页无 Node、Shell、文件系统或通用 Tauri 权限 |
| 标题附加本机 IP、业务页自定义托盘提示 | 最小化本机标识披露 | 不迁移；系统声明不包含用户名、IP 或硬件指纹 |
| renderer console 转发 | 有界结构化诊断日志与脱敏导出 | 已替代；不把敏感业务参数、响应或 URL 写入诊断包 |
| 自动更新、开机启动、单实例、退出确认 | 签名更新、OS 登录启动、单实例、有界排空退出 | 已实现；更新和退出会先停止新原生调用，并等待在途调用及持久账本收尾 |

## 尚不能由源码替代的验收

- `dllWinTop`、OCX 注册、驱动安装、厂商弹窗和 `installRun` 必须用真实签名插件在隔离 Windows 环境验证，不能恢复旧版 100ms 全局抢焦点轮询来假定兼容。
- 普通 Chrome/Edge 是否仍依赖两个旧 localhost 端点，必须以代表性关键流程 HAR 判断；Tauri 自身不会依赖 HTTP。
- NSIS/MSI、x86/x64 宿主、升级保留、Authenticode、真实启动、插件黄金矩阵和最终切换审批必须产生独立签名证据后才能 GO。
