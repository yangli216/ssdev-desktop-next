# 隐私优先的生产诊断

SSDEV Desktop 的诊断目标是定位客户端边界故障，而不是复刻业务请求。日志采用结构化 JSON 事件，只记录稳定事件码、版本、数量和必要的插件/服务策略标识。

## 永不记录

- 插件调用 `parameters`、`ResData` 或原生组件返回内容
- SSO 登录参数、用户标识、令牌、科室、租户
- 业务 URL、更新 URL、插件仓库 URL
- 配置、插件、进程或可执行文件的绝对路径
- 截图内容、悬浮窗上下文、反馈正文
- 未分类的原始错误字符串或调试格式；故障只记录稳定 `event_code` / `error_code`

允许记录的内容包括应用版本、操作系统类别、CPU 架构、协议版本、插件 ID/版本、宿主架构、服务/插件/隔离项数量，以及签名策略是否启用。插件 ID 受可移植标识规则约束，不得承载业务数据。

## 有界存储

- 每个 JSON 事件最多 64 KiB；超过上限时用固定的 `diagnostic-event-oversized` 事件替代。
- 每个日志文件最多 5 MiB，保留当前文件和 5 个轮转文件。
- 日志写入失败和超限事件只累加计数，不阻断业务运行。
- 只接收 `ssdev_desktop_core`、`webplus_controller`、`webplus_plugin_package` 和诊断组件自身的 INFO 及以上事件，不允许通过环境变量扩大到第三方依赖或 DEBUG/TRACE。

## 启动失败反馈

Release 构建不显示终端窗口，因此初始化错误不能只写标准错误后静默退出。桌面端按运行路径、诊断、配置/本地存储、签名策略、插件运行时、核心服务和桌面窗口七个阶段维护稳定启动状态。任一阶段使 Tauri 初始化失败或启动期主线程 panic 时，Windows 会显示原生错误对话框，提供固定错误码、处理建议和当前用户的日志目录；不会把底层错误字符串、业务地址或组件路径复制到对话框及日志。

控制窗口创建后必须在 15 秒内通过 `frontend_ready` 到达 Rust IPC。WebView2 损坏、前端资源缺失或页面脚本没有挂载时，即使进程仍在运行，也会记录 `frontend-startup-timeout` 并显示原生提示，不再表现为长期空白且没有反馈。迟到的就绪信号会被记录，但同一次启动只提示一次。

日志目录内还会以不超过 4 KiB 的 `startup-failure.json` 保存最近一次稳定错误码、摘要、建议和时间，不包含原始异常、URL、路径或用户数据。控制前端成功到达 Rust IPC 后不会删除历史故障，而是原子写入 `resolvedAtUnixMs` 和实际恢复它的 `resolvedByAppVersion`；因此实施人员可以区分“当前仍未恢复”和“旧版本曾失败、当前版本已正常启动”，旧 schema 1 标记会在首次成功启动后升级为 schema 2。就绪和 15 秒超时共用一个互斥状态机，刚好发生在截止边界的恢复不会在就绪之后再留下未解决标记。诊断初始化本身不可用时会尽力写入该固定文件；目录无写入权限时仍至少显示错误码。正常进入控制台后，可以在“安全与诊断”直接点击“打开日志目录”，无需人工猜测操作系统路径。

## 主动导出

本地控制台的“导出脱敏诊断包”会创建一个新的 `.zip` 文件，绝不覆盖已有文件。包内仅包含：

- `manifest.json`：版本、平台、业务桥接协议版本、内部插件宿主协议版本、能力数量、签名策略状态、信任密钥总数及 active/retired/revoked 脱敏计数、业务来源/服务/方法授权数量、插件调用并发上限/当前占用/容量拒绝/执行槽超时/维护拒绝/退出期拒绝/调用方脱离等待计数、controller 当前准入状态、是否全局维护及正在维护的插件数量、持久调用协调可用性/当前准入/运行中/内存结果/账本记录/落盘失败计数、活动宿主数及累计启动成功/失败计数、当前运行累计恢复的插件安装事务数量、安装前成功预检的架构宿主数量、预检失败次数和日志健康计数；不包含具体 keyId、公钥、operationId、origin、pluginId、serviceId、method、请求、响应、插件目录或事务路径。
- `logs/ssdev.log*`：上述有界结构化事件，未压缩读取总量最多 32 MiB。

导出只读取应用管理目录内的固定日志文件名，并拒绝符号链接、目录或其他非普通文件，防止把任意本机文件夹带进诊断包。导出命令只接受本地控制窗口调用，业务 WebView 和截图遮罩没有该能力。诊断包仍可能包含内部插件 ID 和版本，因此应通过组织批准的支持渠道传输，并按内部运维数据处理。

## 自动门禁

`ssdev-diagnostics` 的测试覆盖原子轮转、固定文件数、已有目标不覆盖、符号链接拒绝、ZIP 内容和 manifest 隐私字段。运行时测试证明 DEBUG 事件和非白名单依赖事件不会落盘；源码测试还扫描所有生产 tracing 宏，若新增事件直接包含请求、响应、URL、路径、参数或原始错误字段，CI 会失败。

Windows 安装包冒烟会在每次启动前写入一个合成的未恢复 schema 1 标记；只有已安装前端实际到达 IPC，并把它升级为 schema 2、写入本次应用版本和恢复时间后，安装、原位升级或候选版本启动门禁才会继续。
