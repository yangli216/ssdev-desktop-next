# 隐私优先的生产诊断

SSDEV Desktop 的诊断目标是定位客户端边界故障，而不是复刻业务请求。日志采用结构化 JSON 事件，只记录稳定事件码、版本、数量和必要的插件/服务策略标识。

## 永不记录

- 插件调用 `parameters`、`ResData` 或原生组件返回内容
- SSO 登录参数、用户标识、令牌、科室、租户
- 业务 URL、更新 URL、插件仓库 URL
- 配置、插件、进程或可执行文件的绝对路径
- 截图内容、悬浮窗上下文、反馈正文
- 未分类的原始错误字符串或调试格式；故障只记录稳定 `event_code` / `error_code`

允许记录的内容包括应用版本、操作系统类别、CPU 架构、协议版本、插件 ID/版本、宿主架构、服务/插件/隔离项数量，以及签名策略是否启用。插件 ID 受可移植标识规则约束，不得承载业务数据。

应用更新签名包已经通过验证、但解包或系统安装程序启动失败时记录稳定事件 `app-update-install-handoff-failed` 和错误码 `updater-install`；不记录更新 URL、文件路径或安装器原始错误。此时 controller 与持久协调器已经恢复准入，原业务窗口继续可用。

下一次更新尝试清理下载中崩溃遗留的固定前缀普通文件时记录 `app-update-stale-downloads-cleaned` 和清理数量，不记录临时目录、文件名或更新时间。

更新检查、下载连接、下载中断及非成功 HTTP 状态分别使用 `app-update-check-failed`、`app-update-download-failed`、`app-update-download-interrupted` 和 `app-update-server-error`。控制台只显示稳定错误码、网络/代理/证书/服务等处理方向及可选 HTTP 状态，不显示 updater/HTTP 原始错误、端点、下载地址或安装器路径。

## 有界存储

- 每个 JSON 事件最多 64 KiB；超过上限时用固定的 `diagnostic-event-oversized` 事件替代。
- 每个日志文件最多 5 MiB，保留当前文件和 5 个轮转文件。
- 日志写入失败和超限事件只累加计数，不阻断业务运行。
- 只接收 `ssdev_desktop_core`、`webplus_controller`、`webplus_plugin_package` 和诊断组件自身的 INFO 及以上事件，不允许通过环境变量扩大到第三方依赖或 DEBUG/TRACE。

## 启动失败反馈

Release 构建不显示终端窗口，因此初始化错误不能只写标准错误后静默退出。Windows 主程序在创建 Tauri 或 WebView 前，先通过构建时静态链接的 Microsoft Loader 调用官方发现 API，确认当前用户可发现 WebView2 Runtime；未找到 Runtime 使用 `startup-webview2-runtime`，Loader 调用异常使用 `startup-webview2-loader`，并直接显示原生错误对话框。它不依赖安装目录额外放置 DLL；离线 Doctor 则通过工具包内独立、已签名的相邻 Loader 执行同一发现语义，并能额外识别工具包 Loader 缺失或损坏。该早期路径只从绝对 `%LOCALAPPDATA%` 派生固定日志目录，因此即使 Tauri 尚未建立路径解析器也能尽力留下脱敏启动标记。

随后桌面端按运行路径、诊断、配置/本地存储、签名策略、插件运行时、核心服务和桌面窗口阶段维护稳定启动状态。任一阶段使 Tauri 初始化失败或启动期主线程 panic 时，Windows 会显示原生错误对话框，提供固定错误码、处理建议和当前用户的日志目录；不会把底层错误字符串、业务地址或组件路径复制到对话框及日志。

控制窗口创建后必须在 15 秒内通过 `frontend_ready` 到达 Rust IPC。WebView2 损坏、前端资源缺失或页面脚本没有挂载时，即使进程仍在运行，也会记录 `frontend-startup-timeout` 并显示原生提示，不再表现为长期空白且没有反馈。迟到的就绪信号会被记录，但同一次启动只提示一次。

每个业务窗口在导航回已配置业务来源时另有独立的 30 秒就绪状态机。页面自动调用内部 `business_frontend_ready`，正常、超时和超时后恢复分别记录 `business-frontend-ready`、`business-frontend-timeout` 与 `business-frontend-recovered`；超时以原生对话框给出固定错误码 `business-frontend-not-ready`，用户确认后自动显示本地控制台。首页会直接提供“仅重试失败窗口”：客户端在状态锁内只认领当时仍为超时的窗口，正常、登录跳转中或已经恢复的窗口不会被刷新；重新加载失败会恢复原超时状态，成功后重新进入同一个 30 秒就绪监督。全量刷新仍只保留在项目配置的人工维护区。状态和诊断包只包含活动、加载、导航、就绪、超时及累计恢复计数，不记录窗口标签或 URL；SSO 等非业务来源导航不会触发超时。

每个通过来源与受控进程边界并完成 WebView 构造的业务窗口还记录 `business-window-created`，只包含应用版本，不包含窗口标签、URL 或来源。业务页就绪、超时和恢复事件同样只增加应用版本，不记录页面身份。Windows 候选包门禁会加载仅绑定本机回环地址、无页面脚本的确定性业务测试页，同时要求窗口创建和同版本页面就绪事件，证明安装后的 WebView 确实执行注入桥并到达 Rust IPC；该测试 HTTP 服务只模拟业务站点，不承载任何客户端原生通信。它仍不能表示目标网络、账号和真实业务内容可用，正式交付必须由目标环境深度记录证明。

日志目录内还会以不超过 4 KiB 的 `startup-failure.json` 保存最近一次稳定错误码、摘要、建议和时间，不包含原始异常、URL、路径或用户数据。控制前端成功到达 Rust IPC 后不会删除历史故障，而是原子写入 `resolvedAtUnixMs` 和实际恢复它的 `resolvedByAppVersion`；因此实施人员可以区分“当前仍未恢复”和“旧版本曾失败、当前版本已正常启动”，旧 schema 1 标记会在首次成功启动后升级为 schema 2。就绪和 15 秒超时共用一个互斥状态机，刚好发生在截止边界的恢复不会在就绪之后再留下未解决标记。诊断初始化本身不可用时会尽力写入该固定文件；目录无写入权限时仍至少显示错误码。正常进入控制台后，可以在“安全与诊断”直接点击“打开日志目录”，无需人工猜测操作系统路径。

客户端无法进入控制台时，独立 Windows 项目交付工具包提供 `ssdev-desktop-doctor.exe`。它先从工具同目录以绝对路径加载受完整清单保护、经过 Microsoft Authenticode 复验的 `WebView2Loader.dll`，调用官方版本发现 API 验证当前用户是否真的可被 Loader 找到 Runtime；不依据可能残留的安装注册项，也不创建 WebView。结果只保留 `available`、`unavailable`、`probe-unavailable` 和经过四段数字及可选 `beta`、`dev`、`canary` 固定后缀白名单的版本。

Doctor 默认只读当前用户 `%LOCALAPPDATA%\com.bsoft.ssdev.desktop\logs`：`inspect` 输出 Runtime 状态、固定启动码、是否已恢复和日志聚合，`collect <新的绝对 .zip 路径>` 生成离线诊断包。轮转日志按旧到新解析，最近一次非重复控制前端就绪会把此前启动错误标为历史；只保留其后最多 16 种最新 WARN/ERROR 的可移植事件码、错误码和次数，过多摘要项、无效 JSON 或超限行只输出有界计数，`message` 和其他字段不会进入摘要。工具不启动 Desktop、不修改应用数据、不读取配置、插件、持久调用账本、业务缓存或浏览器资料；原始 `startup-failure.json` 不进入 ZIP，只把白名单错误码和恢复状态写入 manifest。收集结果与归档日志使用同一次快照；Desktop 完全没有留下日志时，Windows 工具仍可生成只含脱敏 Runtime 结果的 manifest。未知或超限标记、链接/异常文件以及已有输出均失败关闭或明确标为需处理。离线包没有运行时服务、插件和授权计数，因此不能替代控制台内的深度部署检查或在线诊断导出。

## 主动导出

本地控制台的“导出脱敏诊断包”会创建一个新的 `.zip` 文件，绝不覆盖已有文件。包内仅包含：

- `manifest.json`：版本、平台、业务桥接协议版本、内部插件宿主协议版本、能力数量、签名策略状态、信任密钥总数及 active/retired/revoked 脱敏计数、业务来源/服务/方法授权数量、插件调用并发上限/当前占用/容量拒绝/执行槽超时/维护拒绝/退出期拒绝/调用方脱离等待计数、controller 当前准入状态、是否全局维护及正在维护的插件数量、持久调用协调可用性/当前准入/运行中/内存结果/账本记录/落盘失败计数、活动宿主数及累计启动成功/失败计数、当前运行累计恢复的插件安装事务数量、安装前成功预检的架构宿主数量、预检失败次数和日志健康计数；不包含具体 keyId、公钥、operationId、origin、pluginId、serviceId、method、请求、响应、插件目录或事务路径。签名插件契约基线条目数和本次运行累计落盘失败只在本地控制台显示，不把具体契约写入诊断包。

启动期检测到离线替换造成公共 API 破坏时记录 `plugin-api-offline-replacement-blocked`，只包含被隔离插件数量；崩溃后完成或撤销 pending 时记录 `plugin-api-baseline-transition-recovered`。准备、提交后收尾或回滚清理无法落盘时分别记录 `plugin-api-baseline-prepare-failed`、`plugin-api-baseline-commit-deferred`、`plugin-api-baseline-abort-deferred`，统一使用稳定错误码 `plugin-api-baseline-io`。这些事件都不记录插件 ID、route、路径、候选契约或原始 I/O 文本。控制台插件清单会以本地可见的插件 ID 标记隔离项，方便用受控安装、仓库回退或显式卸载恢复。

持久调用工作流任务在发布结果前异常终止时记录 `tracked-invocation-workflow-terminated`；随后无法读取账本状态时另记 `tracked-invocation-workflow-reconcile-failed`。两类事件只带稳定错误码，不记录 operation ID、来源、路由、参数、响应、任务错误原文或账本路径。监督层会同步释放等待者和退出排空计数，避免调用永久显示处理中。

持久账本在启动时不可打开不会使桌面主进程退出。控制台首页明确提示非幂等操作暂停，安全页只按 `operation-ledger-path`、`operation-ledger-corrupt`、`operation-ledger-size`、容量或 I/O 等稳定类别显示处置建议；不展示账本路径或底层文件错误。普通业务页面可以继续处理不依赖持久协调的流程，但部署自检保持失败，避免把降级启动误报为可交付。客户端不会提供“一键清空账本”，防止丢失可能已经执行的设备操作证据。

SSO 登录任务在发布结果前异常终止时记录 `sso-login-task-failed`，并把运行状态复位为通用 `sso-login-failed`；应用退出排空任务异常终止时记录 `app-exit-drain-task-failed`，随后标记最终退出就绪并执行受控强制退出。两类事件都不记录任务错误原文、身份字段、URL、调用内容或本机路径。

控制台每 5 秒读取一次桌面核心状态，单次请求最多等待 4 秒。单次或两次瞬时失败保留上次界面，连续 3 次失败后停止自动重试，并把桌面通信、业务页面和部署结论统一标为未知，显示立即重试动作并暂停启动新的业务窗口；旧状态仍可供定位，但不能继续显示为“服务就绪”或“可以交付”。下一次人工重试成功会清除失败计数、恢复周期刷新并短暂提示通信已经恢复。后台刷新不把 IPC 原始错误写入页面或日志。

控制台首次加载的核心项目状态最多等待 15 秒；读取失败或超时后显示固定的重新加载动作，不把 Tauri IPC、文件或底层组件错误写入页面，也不会把半加载页面误报为可用。`frontend_ready` 可以安全重复提交，重试成功后只建立一个状态刷新周期。SSO 事件订阅不参与核心加载成败：订阅拒绝或暂时不可用时，控制台继续加载配置、插件和运行状态，并通过同一 `bridge_status` 周期读取 SSO 聚合状态。启动期快速部署检查另有 4 秒上限；其失败只把部署结论标为检查不可用，不阻断项目配置和插件清单加载。

配置保存/导入、项目导入、插件安装/卸载/重扫/仓库切换、宿主恢复和深度自检等高频操作，把持久操作结果与提交后的只读页面刷新作为两个独立事实。主操作成功后，配置、运行状态、插件清单和快速部署检查按需要分别读取，每类读取最多等待 15 秒且彼此隔离；任一读取失败不会把已经提交的操作改写为“操作失败”，也不显示底层读取错误。控制台会保留明确的成功提示，同时把依赖未复核快照的业务启动、配置提交、插件变更、原生映射和交付结论统一标为不可继续，提示“操作已经完成，请勿重复执行”，并只提供状态刷新动作。并发刷新按字段合并和串行提交，后到的局部成功不能误清除其他仍未读取的字段；全部缺失字段成功复核后才恢复提交入口。
- `logs/ssdev.log*`：上述有界结构化事件，未压缩读取总量最多 32 MiB。

导出只读取应用管理目录内的固定日志文件名，并拒绝符号链接、目录或其他非普通文件，防止把任意本机文件夹带进诊断包。导出命令只接受本地控制窗口调用，业务 WebView 和截图遮罩没有该能力。诊断包仍可能包含内部插件 ID 和版本，因此应通过组织批准的支持渠道传输，并按内部运维数据处理。

本地控制台的“插件宿主明细”按活动路由汇总插件 ID、x86/x64、服务数量和宿主状态。宿主尚未被调用时显示“按需待机”，成功启动后显示“运行中”，启动或运行失败后的短退避窗口显示“启动退避”；退避结束后保留“等待重试”，直到下一次真实调用启动成功或路由被替换，避免刷新周期错过短暂退避而把故障误报成普通待机。同一运行路由还保留累计失败次数和最后一个稳定 controller 诊断码。控制台每 5 秒只读刷新一次运行状态，刷新不触发宿主启动，瞬时 IPC 失败也不会清空已显示的有效快照。失败行可由本地操作员立即恢复精确插件和架构的宿主；该操作只启动或复用隔离宿主并完成原生初始化与 Health，不发送 DLL 导出、COM 方法或 EXE/BAT 业务调用，也不修改路由和插件文件。它可跳过一次短退避，但仍受退出、全局重载和目标插件维护生命周期约束。该明细不包含插件目录、厂商错误、业务参数或响应，并且不会进入业务 WebView。诊断包继续只保存聚合宿主计数，避免把本地插件拓扑无必要地扩散到导出文件。

原生初始化失败不再全部压缩为同一个笼统错误。受信任宿主只把 `NativeError` 的固定类别传给 controller，后者再通过白名单转换为路径无关的稳定码，例如组件缺失、路径越界、DLL、COM/OCX、EXE/BAT 或不支持的声明；详细加载器、注册表、厂商和文件错误文本仍留在宿主边界内且不会写入控制台或结构化日志。未知宿主代码一律降级为 `native-host-error`，不能借错误字段向控制台夹带数据。控制台根据稳定码给出位数、依赖、导出、COM 注册、文件完整性或客户端修复建议；建议不替代深度自检和真实硬件黄金矩阵。

候选宿主预检的本地操作员结果是独立的结构化类型，只包含插件 ID、可确定时的 x86/x64 和稳定诊断码。插件安装、仓库更新、本地映射激活以及深度部署自检都从该类型生成提示，不再格式化内部 `ControllerError`；生命周期维护等尚未进入具体架构宿主的失败会明确省略架构，而不是猜测。

## 自动门禁

`ssdev-diagnostics` 的测试覆盖原子轮转、固定文件数、已有目标不覆盖、符号链接拒绝、ZIP 内容和 manifest 隐私字段。运行时测试证明 DEBUG 事件和非白名单依赖事件不会落盘；源码测试还扫描所有生产 tracing 宏，若新增事件直接包含请求、响应、URL、路径、参数或原始错误字段，CI 会失败。

Windows 安装包冒烟会在每次启动前写入一个合成的未恢复 schema 1 标记；只有已安装前端实际到达 IPC，并把它升级为 schema 2、写入本次应用版本和恢复时间后，安装、原位升级或候选版本启动门禁才会继续。
