# SSO 安全边界

SSO 是独立于业务 WebView 导航权限的敏感网络流程。即使发布方为旧业务站点签署了 `allowInsecureHttp` 例外，客户端也不会通过 HTTP 发送登录标识、租户、角色或科室信息。

## 传输约束

- SSO POST 端点固定从当前主业务地址派生为 `logon/ssoLogin`，且必须是无凭据、无片段的 HTTPS URL；
- 客户端使用系统 TLS 信任，不允许无效证书，也不跟随任何 3xx 重定向，避免 307/308 把请求正文转发到其他来源；
- 连接上限为 10 秒，总请求上限为 30 秒；
- 响应体最多 64 KiB，即使服务器没有提供 `Content-Length` 也在流式读取时执行上限；
- 输入字段最多 1 KiB，返回身份字段最多 16 KiB，并拒绝空值、控制字符、对象和数组。

旧启动器传入的 `--uid`、`--rid` 和 `--deptId` 只接受每项最多一次、紧邻的非选项值。重复参数、缺值、只有角色/科室而没有用户标识或超限值都在联网前失败。日志与诊断包只记录通用事件码，不复制这些值。

同一客户端实例同时只允许一项 SSO 请求。当前请求结束前到达的新请求以 `sso-already-running` 明确拒绝，防止两个身份响应按不可预测的完成顺序打开业务窗口。Rust 保留的状态只有“是否进行中”和最后一个固定错误码；控制台同时读取持久状态并订阅实时状态事件，因此不会因页面加载时序漏掉错误。

## WebView 权限

SSO 返回后，客户端按照现有服务端契约构造经过百分号编码的登录导航。`navigationOrigins` 只允许 WebView 完成受控导航，不注册远程 Tauri ACL，也不能调用插件、截图、窗口、安装、更新或诊断命令。

当前服务端契约仍把 `uid`、`urt` 和 `urtDept` 放在登录导航查询参数中。客户端不会记录完整 URL，但查询令牌仍可能进入服务端访问日志、代理日志或浏览器历史。长期应由服务端改为一次性短码或 `Secure`、`HttpOnly`、`SameSite` Cookie；完成协议升级前，代理和服务端必须关闭查询参数日志，并将令牌设置为短时、单次使用。

## 验收要求

正式切换前必须在院内证书环境验证：有效登录、过期证书、主机名不匹配、HTTP 地址、跨域/同域重定向、超大响应、非标量字段和超时。任何失败都只能产生通用 `sso-login-failed` 或 `sso-arguments-invalid` 事件，不得在日志中出现用户、租户、角色、科室、令牌或 URL。
