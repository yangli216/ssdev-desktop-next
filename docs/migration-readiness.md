## 当前旧资产证据基线

- 只读审计确认现有旧配置样本包含 5 个 HTTP 业务来源；报告没有复制具体地址。它们必须优先迁移到 HTTPS，暂时保留的每个来源都要进入 schema 2 签名策略的单独风险评审。
- 旧 Electron 主进程源码确认曾监听本机 45121，并提供 `/desktop/notice` 与 `/desktop/cache`；旧 Go WebPlus 源码确认曾监听 7711。服务端代码存在只能证明历史能力，不能证明当前仍有浏览器或外部进程调用。
- 当前可用的旧前端样本未观察到 7711/45121 静态调用引用，但没有代表性业务 HAR、真实账号流程或外部进程清单，因此结论仍是“未观察到”，不是“已证明无依赖”。在这些证据补齐前，不交付 HTTP adapter，也不宣布可以永久删除兼容评审项。
- 当前没有生产插件目录、黄金请求/响应、旧 keymap 或完整 processes 样本；相应 ABI、安装动作、脚本快捷键和受控进程迁移仍必须以真实材料验证。

## 正式切换前需要外部输入或真实环境

开始执行前先用 [真实项目试点材料预检](pilot-readiness.md) 生成脱敏材料集合摘要，并在 schema 2 manifest 中把正式迁移审计角色精确绑定到相应类别输入。预检通过只表示以下输入已经明确提供或经批准确认为不适用；所有语义、签名、硬件、升级和生产切换门禁仍需分别执行。

1. 由组织发布系统提供 Ed25519 生产公钥，并把私钥保存在 KMS/HSM 或受控 CI 中。生产信任库至少为插件、来源策略和项目部署包准备 active 用途密钥；项目交付密钥应与插件发布密钥隔离。
   同一受控签名流程还需生成精确的业务 origin/service/method、SSO 导航与外链来源策略；旧 HTTP 业务站点必须经过风险确认后单独放行。
2. 提供当前生产插件目录及代表性脱敏请求/响应；先运行迁移审计，再通过 `ssdev-plugin-tool` 建立隔离暂存、签名请求、确定性包和覆盖全部 service/method 的黄金矩阵草稿。替换占位符、清除 `draft` 标记后完成实机回归。
3. 在真实 Windows x64 设备上执行 `scripts/test-windows.ps1`，同时覆盖实际 32 位 DLL、已注册 OCX、硬件驱动和院内证书环境。
4. 提供业务前端构建产物，并在代表性账号、设备和关键流程中导出 HAR；将两类输入写入试点 manifest 的对应类别和 `migrationAuditBindings`，再由正式 `ssdev-migration-audit` 自动派生，确认普通 Chrome/Edge 是否仍直连 `7711` 或 `45121`。HAR 中缺失、相对或损坏的 `request.url` 不计入已扫描请求，并以 `browser-har-scan-incomplete` warning 阻断生产判定，不能用一个有效请求掩盖其余无效条目。只有 HAR 确认且调用方无法同步迁移时，才交付默认关闭、带会话挑战的独立 HTTP 兼容 adapter；Tauri 内部不依赖它。
5. 确认旧 `/desktop/notice`、`/desktop/cache` 是否仍有外部进程调用。浏览器调用纳入上述 HAR 门禁；非浏览器调用优先改为经过身份校验的命名管道，仅在调用方无法改造时保留受限 HTTP adapter。
6. 提供仍在用的 `processes` 和 `keymap.json` 样例，并先运行 `ssdev-migration-audit`，用于生成生产签名进程策略和声明式动作映射；旧版 Shell 启动与 `eval(snippet)` 不迁移。
7. 在 Windows 构建机提供代码签名证书或 HSM/KMS 签名命令，以及独立的 Tauri 更新签名私钥；CI 已覆盖合成版本升级/配置保留/启动/卸载，仍需用真实上一生产版本重复升级门禁并演练失败回滚。两类私钥均不得进入仓库。

## Go / No-Go 规则

只有以下条件同时满足才能替换旧 Electron/WebPlus：

- 所有生产插件黄金用例通过，且没有调用约定需要继续猜测 ABI。
- Windows 双架构门禁、安装升级、SSO、多窗口、截图和实际硬件端到端测试全部通过。
- 生产信任库非空，安装包和插件均完成组织签名。
- schema 7 生产策略绑定本次批准的试点材料集合、指定上一生产版本及其发布元数据/全产物清单、最终 Windows 产物清单、来源策略、插件发布集合、QA/发布信任库和定稿矩阵，并先由最终审批职责签名；迁移 schema 3 与 Windows 包 schema 6 证明正式审计来自该材料集合、升级确实从指定版本执行、候选卸载后指定上一版本可以保留配置并重新启动、真实业务页面在目标网络到达 Rust IPC，审计和实际安装使用同一来源策略，包内信任库/宿主与硬件矩阵输入一致，并按切换前冻结清单设置迁移资产最低覆盖；schema 3 GO 决策必须携带匹配策略的封套及两份信任库身份，不存在的资产类别必须显式批准为 `0`。
- 在目标部署模式下关闭 HTTP 后，Tauri 内业务功能无回退依赖。
- 已完成分批发布与旧版本可回滚演练。
