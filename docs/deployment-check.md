# Windows 项目部署自检

控制台“安全与诊断”页面提供一键部署自检，用于回答当前机器和项目配置是否具备交付条件。自检直接读取当前 Rust 运行时状态，不根据页面缓存推测结果；启动时自动执行一次，也可以在修复后手动重新执行。

## 判定范围

自检覆盖项目交付最常见的本机边界：

- WebView2 已实际加载控制台并成功到达 Rust IPC；
- 默认业务地址或业务环境已经通过配置校验；
- 当前业务来源获得部署策略授权，包括项目允许使用的内网 HTTP；还会把全部已配置业务来源与当前插件公开的 `serviceId + method/alias` 做覆盖核对，要求每个来源至少能访问一项已安装能力、每条公开调用路由至少被一个当前来源授权；
- 正式版插件处于 Ed25519 严格签名模式，且至少有一把 active 密钥；
- Windows 安装目录同时包含 x86、x64 隔离宿主；
- 插件没有被隔离，磁盘重新发现的服务数量与控制器当前活动服务数量一致；
- 持久调用账本可以接受调用，没有影响防重放和结果找回的启动故障；
- 插件安装预检、受控辅助进程和隐私诊断处于可解释状态；
- 在线应用更新是否配置。离线部署不要求在线更新，因此该项只提供信息，不阻塞交付。

在非 Windows 开发机上，x86/x64 宿主文件检查标记为 `info` 并跳过，不能替代 Windows 安装包门禁。

## 结果等级

| 等级 | 含义 | 是否阻塞交付 |
| --- | --- | --- |
| `pass` | 当前状态满足要求 | 否 |
| `warning` | 功能仍可运行，但交付或排障能力不完整 | 否 |
| `fail` | 项目地址、安全边界或关键运行时不可用 | 是 |
| `info` | 可选能力状态或当前平台无法执行的检查 | 否 |

只有 `failures == 0` 时报告才返回 `ready: true`。没有安装插件属于提醒，因为空项目仍可先完成客户端部署；插件加载失败、磁盘服务与控制器活动服务数量漂移、业务来源无法访问任何已安装能力，或某条公开插件调用路由未被当前任一业务来源授权都属于阻塞。覆盖检查包含方法规范名和 alias，但只核对声明式授权，不发起真实原生调用。未配置在线更新不影响隔离网络使用离线 NSIS。

## 不替代的验证

应用内自检会在插件安装锁内重新读取当前插件和映射，并与控制器活动服务对账；它不主动访问业务系统、SSO 或插件仓库，避免在启动阶段发送网络请求，也避免把认证页面的可达性误判为客户端故障。正式交付仍需在目标 Windows 机器执行：

1. 打开实际业务环境；
2. 使用项目测试用例调用关键 DLL/COM 方法；
3. 验证需要的读卡器、打印机等硬件；
4. 导出一次脱敏诊断包；
5. 按组织流程验证安装、升级、回滚和卸载。

自检结果只返回稳定检查 ID、计数、面向实施人员的摘要与处理建议。结构化日志仅记录通过、提醒和失败数量，不写入业务 URL、文件路径、调用参数或原生响应。
