# Windows 项目部署自检

控制台“安全与诊断”页面提供快速检查和深度自检，用于回答当前机器和项目配置是否具备交付条件。两者都直接读取当前 Rust 运行时状态，不根据页面缓存推测结果。启动及配置、插件变化后的自动刷新使用快速检查，不主动创建插件宿主；Windows 上由用户点击“深度自检”或导出现场记录时，还会为当前每个已验证插件及其实际 x86/x64 架构启动隔离候选宿主，完成认证、二次校验和原生初始化后再返回 Health。DLL 会加载依赖并解析全部声明导出，COM/OCX 会实例化声明类并解析成员，EXE/BAT 会校验发布清单或本地完整性清单中的 SHA-256 并建立运行期只读保护，但不会执行；整个过程不调用业务方法，也不替换活动路由。

深度预检失败时，报告会指出首个阻塞插件、实际 x86/x64 架构和路径无关的稳定诊断码，并按组件缺失、DLL、COM/OCX、进程入口、架构或宿主安装问题给出处理建议。候选插件安装、仓库更新、本地映射激活和深度自检共用同一结构化失败边界；原生错误原文、绝对路径和厂商文本不会拼接到控制台、导出记录或结构化日志中。

## 判定范围

自检覆盖项目交付最常见的本机边界：

- WebView2 已实际加载控制台并成功到达 Rust IPC；
- 默认业务地址或业务环境已经通过配置校验；
- 当前业务来源获得部署策略授权，包括项目允许使用的内网 HTTP；还会把全部已配置业务来源与当前插件公开的 `serviceId + method/alias` 做覆盖核对，要求每个来源至少能访问一项已安装能力、每条公开调用路由至少被一个当前来源授权；
- 正式版插件处于 Ed25519 严格签名模式，且至少有一把 active 密钥；
- Windows 安装目录同时包含 x86、x64 隔离宿主；
- 插件没有被隔离，磁盘重新发现的完整插件清单与控制器激活时保存的清单快照一致；比较覆盖插件身份/版本、目录、serviceId、架构、原生入口、方法/alias、参数、超时和扩展字段，不只比较服务数量；
- 持久调用账本可以接受调用，没有影响防重放和结果找回的启动故障；
- 快速检查展示本次运行的历史宿主预检异常；深度自检则要求当前插件在实际架构宿主中重新完成原生加载与 Health 预检，失败直接阻塞交付；
- 在线应用更新是否配置。离线部署不要求在线更新，因此该项只提供信息，不阻塞交付。

在非 Windows 开发机上，x86/x64 宿主文件检查标记为 `info` 并跳过，不能替代 Windows 安装包门禁。

## 结果等级

| 等级 | 含义 | 是否阻塞交付 |
| --- | --- | --- |
| `pass` | 当前状态满足要求 | 否 |
| `warning` | 功能仍可运行，但交付或排障能力不完整 | 否 |
| `fail` | 项目地址、安全边界或关键运行时不可用 | 是 |
| `info` | 可选能力状态或当前平台无法执行的检查 | 否 |

只有 `failures == 0` 时报告才返回 `ready: true`。报告的 `deep` 明确区分本次结果是否完成了 Windows 宿主主动预检；快速检查只表示当前静态和运行态没有发现阻塞，不能声称当前原生依赖已经重新验证。没有安装插件属于提醒，因为空项目仍可先完成客户端部署；插件加载失败、深度宿主预检失败、磁盘完整清单与控制器活动快照漂移、业务来源无法访问任何已安装能力，或某条公开插件调用路由未被当前任一业务来源授权都属于阻塞。即使服务数量相同，版本、方法、alias、参数或入口变化也会被识别。覆盖检查包含方法规范名和 alias，但只核对声明式授权，不发起真实原生调用。未配置在线更新不影响隔离网络使用离线 NSIS。

## 现场记录导出

“导出深度自检记录”会在 Windows Rust 端重新执行包含当前插件宿主 Health 预检的完整自检，而不是把页面上一次显示的结果原样保存。在非 Windows 开发预览环境中不伪造宿主预检，导出结果保持 `deep: false`。输出是有 128 KiB 硬上限的 JSON，包含 schema、生成时间、Desktop 版本、操作系统、架构和稳定检查项；不包含业务 URL、配置路径、插件目录、调用参数、原生响应或底层错误原文。客户端只允许受限本地控制窗口调用，并使用暂存文件同步落盘后执行不覆盖提交；相同目标已存在、目标不是绝对路径或父目录是符号链接时导出失败。

记录明确带有 `evidenceLevel: "unsigned-local-record"`。它适合项目实施交接和修复前后对照，但不提供发布者身份、目标机身份或不可抵赖性，不能代替真实插件黄金矩阵、Windows 包验收和生产切换 Go/No-Go 签名证据。

## 不替代的验证

应用内自检会在插件安装锁内重新读取当前插件和映射，并与控制器活动清单快照对账；它不会自动加载磁盘变化，因为人工替换目录不能绕过候选宿主预检和可恢复安装事务。管理员显式执行“重新扫描”时，客户端会先重新验签全部有效组件并逐个完成候选宿主预检，全部成功后才进入一次全局维护窗口替换路由。自检不主动访问业务系统、SSO 或插件仓库，避免在启动阶段发送网络请求，也避免把认证页面的可达性误判为客户端故障。正式交付仍需在目标 Windows 机器执行：

项目部署包导出会在同一插件安装锁内复用可移植的硬门禁：联合清单与路由、来源—方法双向授权覆盖、磁盘与活动服务一致性，以及每种实际架构的候选宿主预检。预检直接使用确定性封装后、即将写入项目包的候选组件，容器写入还会复算组件大小和摘要，避免外部文件变化让“通过检查的目录”和“实际交付的包”分离。它不会用更新端点、诊断组件、目标网络或真实业务调用等机器特定状态阻止导出；目标机导入前还会按目标机器现状重新执行完整项目预检。

1. 打开实际业务环境；
2. 使用项目测试用例调用关键 DLL/COM 方法；
3. 验证需要的读卡器、打印机等硬件；
4. 导出一次脱敏诊断包；
5. 按组织流程验证安装、升级、回滚和卸载。

自检结果只返回稳定检查 ID、计数、面向实施人员的摘要与处理建议。结构化日志仅记录通过、提醒和失败数量，不写入业务 URL、文件路径、调用参数或原生响应。
