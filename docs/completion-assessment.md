# SSDEV Desktop Next 完成度评估

评估日期：2026-08-30

## 结论

项目已经具备进入“真实业务验收”的工程条件，但尚不能宣布生产切换完成。代码、自动测试和合成安装包门禁覆盖了 Tauri 桌面壳、无 HTTP 的 Web Bridge、x86/x64 隔离插件宿主、DLL/COM/OCX/EXE/BAT、签名插件生命周期、最小 Rust DLL 插件脚手架、用公开测试密钥制作双架构签名包并经过正式发布集合物化、由生产黄金矩阵包装器分别实际调用 x86/x64 宿主及核对 schema 2 证据、无密钥源检查、相对上一签名包及正式目录内多版本的 Web API 兼容门禁、工作台与发布工具共用的类型化 Web 客户端生成、无需桌面或硬件的严格前端 fixture invoker、从结构完整黄金矩阵生成同路由 Web fixture、把单插件客户端与 fixture 原子绑定为带来源摘要清单且可在业务 CI 重复验证的 Web 接入包、默认 CI 生成的可重复 Web Bridge SDK `.tgz` 与锁定源码摘要清单及离线 ESM/TypeScript 消费者冒烟、一个或多个精确 Web kit 与同一 SDK 制品的离线严格联合编译、插件身份/公开路由冲突检查和全路由组合冒烟、业务 HAR 有效/跳过请求分离统计及不完整扫描阻断、单包及多包发布集合与黄金矩阵联合离线检查、批准发布集合的一次性验收目录生成、现场插件目录到硬件证据的逐包摘要绑定、硬件矩阵与安装后插件信任库及 x86/x64 宿主的逐字节身份对账，以及生产策略对试点材料、指定上一生产版本、候选与上一版本 Windows 产物清单、批准插件集合/信任库/矩阵和八类迁移资产最低覆盖的精确约束、应用更新、配置迁移、SSO、多窗口、截图、诊断和供应链证据。剩余风险主要不是继续猜测实现，而是缺少生产插件、真实硬件、业务 HAR、生产签名体系和上一生产安装包等外部材料。

试点材料现在可以用独立只读工具建立脱敏移交基线：十类核心材料必须实际提供，旧快捷键、受控进程和外部本机 HTTP 调用方三类条件材料必须提供或引用明确的不适用审批；schema 2 manifest 还把正式迁移审计的配置、插件、快捷键、业务前端、HAR 和签名策略角色精确绑定到对应类别。上一生产 Windows bundle 在这一入口就会按 `artifacts.json` 复算完整文件集合、大小和 SHA-256，并要求唯一顶层 NSIS，缺失、额外或替换文件不能被材料摘要掩盖。报告绑定每类内容、角色摘要与总集合摘要且不保存路径、项目标签或审批原文。接收方可以严格加载报告并对收到的同一 manifest 和材料目录重算逐字段身份，阻断报告、清单、角色或文件被替换。该报告始终声明后续验证仍然必需，因此不会把输入收齐替代迁移审计、黄金矩阵、Windows 实机或生产 Go/No-Go。

试点预检的命令行结果也已经形成可执行闭环：不完整的 `create` 或 `verify` 直接列出同一机器报告中的排序稳定阻断码和逐项处理动作，完整时只公开材料集合 SHA-256，并把下一步限定为接收方复验或从已复验集合运行迁移审计。全部合法阻断码都必须拥有有界、脱敏建议才能通过报告校验；现场和 CI 不必先打开 JSON 猜测缺项或理解内部码名，同时不会泄露材料路径、项目标签或审批引用，也不会把复验一份真实但不完整的报告误报为准入成功。

首次建档也不再依赖人工复制示例 JSON。`init` 从代码中的固定类别生成不可覆盖清单、可移植建议路径和精确审计绑定；三个条件类别默认仍要求材料，工具不写入演示审批号，也不创建可能被误认成真实证据的占位文件。实施人员只有取得项目批准后才能显式改为不适用，减少每个试点重复抄写和把示例值带进正式材料的风险。

材料整理和正式交接也已分层：`check` 复用同一稳定扫描与阻断建议，可重复执行但不落盘报告；就绪时仍不公开材料集合摘要，只指向 `create`。因此实施人员无需为每轮路径修正制造不可覆盖废报告，也不能把草稿控制台结果冒充接收方可复验的交接记录。

正式迁移审计不再以“报告已写出”掩盖内容阻塞。报告和证据落盘后，CLI 从与证据相同的 finding 集合聚合 critical/warning code、出现次数和有界处理动作，不回显来源路径或 finding 消息；存在阻断返回 `3`，使自动签名和发布默认停止，零阻断返回 `0` 仍明确需要插件矩阵、Windows 包和最终 Go/No-Go。相同 code 的严重级别或建议不一致会在写正式输出前失败。

真实插件矩阵的正式运行日志也已收敛到相同的现场边界。包装器不再用 `cargo run` 回显全部路径参数；发现、验签、矩阵、宿主、输入漂移、设备结果和证据写入失败分别映射为稳定阻断码与固定动作。黄金差异只累计失败数，不打印用例名、插件 ID、期望响应、实际设备返回、路径或底层错误，任何失败都不生成证据；成功只公开覆盖聚合和 `CLEAR`，并明确继续独立 Windows 包与最终判定。

最终切换也增加了送签前的只读关口。`precheck` 使用已签生产策略、发布/审批信任库、证据信任库和三份未签 QA 证据，直接复用最终判定器输出同一组稳定阻断码；输入在读取期间变化即失败，不写决策或伪造封套。每个阻断码都绑定固定、脱敏的处理动作，`precheck` 与最终 `decide` 使用同一映射，未知码不能进入当前 schema 的正式决策。它让版本、摘要、证据时效、迁移覆盖、宿主身份或 Windows 回退缺口在占用三套 QA KMS/HSM 前暴露并可直接处理，最终 `decide` 仍重新验签全部封套并再次判定。

最终签名 GO 也不再只依赖人工按摘要寻找归档文件。`verify-go` 对最终决策封套、策略封套、发布/审批与 QA 信任库、三份证据和三个 QA 封套的十二个原始输入执行前后身份复核，并在决策记录的评估时点重放同一判定函数；只有逐字段重现签名决策才返回 `VERIFIED-GO`，不写新的事实或把历史复验当成一次新的切换授权。

历史可复验不再等同于当前可以部署。schema 8 策略新增人工批准的 `maximumCutoverDecisionAgeSeconds`，范围为 60 秒至 7 天；`check-current-go` 先完成与 `verify-go` 相同的十二输入验签和重放，再使用组织当前受保护的审批与 QA 信任库复验策略、GO 和三个证据封套。`active`/`retired` 键可以验证已有签名，`revoked`、缺失或替换公钥稳定阻断；归档与现行信任库在复验期间发生漂移则失败。现场实际待安装的完整 Windows bundle 还要在检查前后分别按 `artifacts.json` 逐文件复核，并与签名 Windows 证据的 release 元数据、清单、版本和源码精确一致；清单必须恰好包含一个顶层 NSIS，通过结果直接给出其相对路径，另一构建或被替换的安装器不能沿用 GO。最后才使用现场系统时间检查 GO 判定时间，未来时间超过五分钟容差或超过执行窗口同样返回稳定阻断和处理动作，避免密钥紧急吊销后继续部署、误装其他包或长期重放旧 GO；命令不写文件也不执行安装。

## 分层完成度

正式迁移审计现在只从已复验试点 manifest 派生输入和候选安装包的 active 签名来源策略，禁止混入手工路径，并在执行前后复验整个材料集合。生产策略也由 clean 源码、同一试点三件套、候选/上一生产 bundle、批准插件集合和组织 QA 证据信任库自动生成；人员只决定证据时效、GO 执行窗口、覆盖下限和四个职责签名人。schema 8 策略固定 QA 与最终审批信任库，并由现有最终审批职责使用独立 `cutover-policy` 域签名；schema 3 GO 决策固定策略封套和实际两份信任库，同名 keyId 的替代公钥库不能通过判定或签发。迁移 schema 3 与生产策略共同绑定试点材料集合，迁移与 Windows 包 schema 7 及生产策略继续绑定同一来源策略摘要；Windows 包还必须绑定独立的指定上一版本回装启动、应用状态保留结果，以及同版本、近期且包含真实业务页握手的深度部署记录。换材料、换策略、换策略封套、换信任根、复制错误、用其他低版本替代真实升级、只完成候选升级、只完成回装启动、重放过期 GO 或只启动控制台都会失败关闭。

| 层级 | 当前判断 | 可以做什么 | 尚不能证明什么 |
| --- | --- | --- | --- |
| 源码与自动测试 | 可用 | 执行 Rust/前端测试、Windows 双架构原生回归、Linux/macOS/Windows 构建 | 不能替代生产 DLL、OCX、驱动和院内证书 |
| 开发/测试环境验收 | 可以开始 | 导入签名测试插件，核对可视化映射，验证业务 WebView 直连 Tauri、插件更新和应用更新测试端点 | 不能代表生产账号、设备和网络拓扑 |
| 生产试点 | 有条件准入 | 外部输入齐备后在受控 Windows 设备灰度 | 材料未齐前不允许全量替换旧 Electron/WebPlus |
| 生产切换 | 未准入 | 通过严格 Go/No-Go 证据汇总后执行 | 当前缺少真实插件矩阵、生产签名、真实升级/回滚和 HTTP 依赖结论 |

## 原平台能力覆盖判断

- 控制台已经从能力罗列改为任务导航：普通用户正常启动直接进入默认业务，需要管理时才回到运行概览；实施人员分别进入项目配置、原生映射和插件管理。独立“项目交付”工作区按源机导出草稿、组织签名后在目标机预检导入、目标 Windows 深度验证的固定顺序承载项目包和现场记录，非 Windows 开发预览不开放可执行的深度门禁。安全页只保留信任边界、运行指标、日志和客户端维护。首页待处理项会直接把快速检查通过或部署阻断引导到项目交付，而不要求实施人员在安全诊断中寻找正式交付动作。
- 单项目工作区已经具有稳定项目身份。项目名称与可移植项目标识必须成对填写，配置校验、首页、普通配置导入差异和项目包预览使用同一字段；项目身份变化不会为单纯配置编辑中断正在工作的业务页面，但整体项目导入仍在提交后关闭旧页面。旧配置没有身份时继续保留业务运行兼容，项目包导出/导入、快速/深度交付结论和 Windows 现场记录则失败关闭，避免匿名包只靠文件名或相似内网地址被送到错误客户。该能力没有扩张为多项目数据库或云端项目中心。
- Windows 项目实施工具已从普通用户安装包中独立：x64 工具包包含离线启动诊断、试点预检、迁移审计、插件发布、统一签名、切换判定、清单复验、正式黄金矩阵运行器和 Windows 包验收包装器，验证机执行矩阵及安装、升级、回退验收不再要求安装 Rust。包验收调用相邻清单、签名和证据 EXE，并复用 Desktop 相同的更新策略解析与流式 Minisign 实现，避免现场工具与运行时接受不同 updater；顶层失败只按工具/源码、输入、业务探针、候选、上一版本、安装、升级回退和证据阶段输出稳定阻断码与固定动作，不泄露 PowerShell 异常或路径，成功也只报告 `CLEAR` 而不冒充最终 GO。Desktop 主程序和离线诊断工具复用同一 WebView2 Runtime 发现语义：主程序通过构建时静态链接的 Microsoft Loader，在创建 Tauri/WebView 前就区分当前用户未发现 Runtime 与 Loader 调用异常并显示原生错误，不要求安装目录携带独立 DLL；Doctor 则通过工具包内已签名的相邻 Loader，在控制台不可达时输出可用、未发现 Runtime、Loader 缺失/损坏与其他探测链异常，不再以安装注册项推断 WebView2 可用。Doctor 随后只读当前用户固定日志和已知启动标记，按最近真实控制前端恢复边界聚合有界稳定错误码，并输出不覆盖的脱敏 ZIP；完全没有日志时也能保存 Runtime 结果。两条路径都不创建 WebView，不扫描配置、插件、账本、业务缓存或浏览器资料，也不把 Loader 原始错误或日志消息带入摘要。工具包固定记录源码提交并以完整 `artifacts.json` 覆盖包装器、说明、元数据、全部 EXE、Microsoft Loader 和 8 份 SBOM；生产构建要求 clean commit、组织签名命令、逐个组织 EXE Authenticode 复验以及 Loader 原有 Microsoft 签名复验，最终归档还必须由组织发布系统签名，CI unsigned 制品只能验证构建链。真实矩阵及 Windows 包证据仍绑定同一源码工作区、候选完整 bundle 和双架构宿主，因此工具分发不会削弱生产证据身份。
- 普通启动已经恢复业务优先语义：存在已授权默认地址时直接创建最大化业务 WebView，隐藏的本地控制台仍完成 IPC 就绪监督并可由托盘恢复；缺少默认地址、启动边界拒绝、托盘不可用、SSO 启动反馈或 SSO 失败时显示控制台。重复启动和托盘左键优先聚焦确定排序的已有业务窗口，没有业务窗口才进入管理页。控制台只在托盘存在且应用未退出时把关闭转换为隐藏，避免没有恢复入口的后台空进程。Windows 候选包门禁会启动仅绑定回环地址、无页面脚本的确定性业务测试页，并同时等待无 URL 的 `business-window-created` 与带候选版本的 `business-frontend-ready`，证明安装后的 WebView 实际完成文档加载和注入桥 IPC，而不只构造空窗口；上一版本保持回退兼容。该测试页不承载客户端原生 HTTP 通信，也不替代目标网络、账号和真实业务页的深度握手证据。

## DLL 映射可视化

内置控制台既展示通过当前信任库验签并重新发现成功的发布插件，也提供可写的本地原生映射工作台。发布插件提供以下只读拓扑：

`插件 ID/版本 → serviceId → x86/x64 与 mainType → mainClass（DLL 相对路径或 COM ProgID）→ 请求方法名 → 原生导出/成员名`

同时展示调用约定、字符集、服务/方法超时、缓存策略、依赖数、参数数和返回类型。绝对插件根目录不进入发布映射数据；隔离插件不进入可调用拓扑。

本地工作台可以选择 DLL/EXE/BAT、只读识别 PE 架构和命名导出，或按 x86/x64 注册视图搜索 COM/OCX 后选择 ProgID/CLSID；管理员可编辑服务、方法、参数、返回值、依赖、字符集和调用约定。插件和映射 ID 统一使用 Windows 可移植 ASCII 规则；工作台在保存前提示，签名清单、仓库、包激活、项目容器和恢复事务在 Rust 边界重新校验，尾随点、Unicode/空格和保留设备名不能由非 Windows 配置机带到现场。保存时组件被复制到固定本地映射根目录，在正确位数的隔离宿主中预检，然后以持久事务原子热加载；普通失败和进程崩溃都会恢复旧目录和路由。未签名 `.ssdev-mapping` 不再因文件选择就加载原生代码：只读结构预检先展示安装/替换、服务、架构、类型、方法和用例范围，明确确认后重新绑定包摘要、Desktop 版本和目标映射状态，复核通过才执行宿主预检与按插件原子激活。编辑器会标记未保存草稿，并在新建、切换、导入或关闭前防止静默覆盖；项目包成功切换后才重载磁盘映射，失败仍保留草稿。独立保存调试用例不会掩盖其他未保存 ABI 字段。工作台还提供同路由现场调用、耗时与结构化结果查看，可保存有界的合成输入并顺序回归 `ResCode`、`ReturnValue` 和关键输出字段，以及导出类型化 Web Bridge 客户端和包含组件/用例的 `.ssdev-mapping`。生成客户端在常见场景直接使用公开 alias/方法名，无输入调用不要求空对象；只在跨服务重名或标识清洗冲突时增加服务前缀或序号，底层路由仍固定为原声明；声明的 COM 属性会进入结果类型，无法从配置证明的属性类型保持为 `JsonValue`。稳定映射可导出仅含 API 与引用组件的最小发布源，并在其目录外生成仍为草稿的正式矩阵种子；签名工具会强校验路由、完整输入和全方法覆盖，正式运行器即使遇到被误改为非草稿的遗留占位符或未解除的精确响应复核标记，也会在启动宿主前失败，同时避免现场用例进入签名插件。COM 注册发现只读元数据且不实例化未知组件；复杂结构体、回调或厂商自定义 ABI 仍需要专用 Rust 适配器。

## 更新机制

### 应用本体

已经实现 HTTPS 更新清单、内置公钥、Tauri Minisign 验签、流式大小上限、崩溃残留更新文件的定向清理、安装前停止插件调用、失败恢复准入并保留原业务窗口，以及成功交接后的进程重启。更新临时根拒绝符号链接，清理只匹配客户端固定前缀的普通文件，不触碰同目录其他内容。运行时检查、下载、中断、HTTP 状态与安装器交接错误均映射为稳定错误码和处理方向，不把私有端点、下载 URL、临时路径或底层原文返回控制台或写入日志。安装交接失败后控制台会退出安装中状态、作废已消费的计划并引导重新检查，不会继续展示一个可重复提交的失效确认。检查和安装阶段都会以目标 Desktop SemVer 重新验证当前签名插件与本地映射的完整集合，在下载前阻止会使现有能力被隔离的应用升级。确认标识绑定精确 pending 更新元数据、Minisign 签名、当前全部签名插件载荷及本地映射确定性内容；安装前和包验签后分别复核，另一轮检查替换 pending 或下载期间任一能力发生变化都会要求重新确认。正式验收仍需生产更新端点、真实签名密钥、代码签名证书以及从上一生产版本执行升级和失败回滚。

### 插件

正式目录生成阶段会按 SemVer 重新验签并比较规格内同 ID 的相邻可安装版本，破坏公共 Web Bridge 契约时在目录落盘前失败；成功报告给出实际比较数且不包含本地路径。目录只包含一个版本时不会冒充历史兼容证明，仍要求用上一批准签名包执行独立 `api-check`。

签名目录的 Windows 身份约束也由客户端独立执行，不依赖官方发布工具先替它清洗输入：全部版本和撤回记录按 ASCII 大小写不敏感 ID 归并，同一身份的拼写漂移、重复版本及可安装/撤回交叠都会被拒绝。仓库查询、更新列表和最终安装使用同一语义；已安装插件与目录规范拼写不一致时只显示一个明确阻断项，不生成可执行安装计划。

磁盘发现和活动路由边界也不再依赖运行机器恰好是 Windows。共享发现器先统计全部目录身份，`Reader`/`reader` 冲突时隔离双方而不根据扫描顺序或单方清单有效性择一运行；controller 对完整路由集合和增量注册再次拒绝不可移植或大小写别名身份，并以规范身份共享维护生命周期。因而 macOS/Linux 配置机、测试工具或内部调用不能制造一个只在目标 Windows 上才暴露的双插件状态。

签名与开发态能力合并也保持单向信任优先级：签名插件根中观察到的规范身份即使未通过清单、验签或 Desktop 兼容检查，仍会阻断同 ID 本地映射进入活动清单。启动、重扫、映射保存和导入不会在签名能力被隔离时把同路由降级到开发实现；实施人员必须显式修复/处理签名目录或更换映射身份。

Release 信任模式同时固定到一次启动身份。正式客户端缺失或损坏 `plugin-trust.json` 时在创建运行时前失败，不接受调试环境覆盖或未签名开关；成功加载后保存原始文档 SHA-256，controller 启动每个签名插件宿主时传递同一摘要，宿主在加载原生组件前重新读取并精确核对。运行期间原路径被替换只能阻断后续宿主启动，不能让桌面内存、受控进程策略和新宿主各自接受不同信任根；合法密钥轮换需要受控更新并重启。

信任库运行期漂移也不会再伪装成普通宿主或厂商组件故障。controller 在创建进程前复核同一摘要，缺失、损坏或替换统一形成路径无关的 `plugin-trust-store-changed`；深度自检给出停止原生调用、修复完整客户端并重启的固定动作。宿主仍在进程内二次核对，覆盖两次检查之间的竞态。

已经实现短期签名目录、独立目录签名用途、精确大小/SHA-256、插件包二次验签、显式 Desktop SemVer 兼容范围、插件 SemVer 防降级、精确版本撤回、x86/x64 宿主预检、按插件维护、原子激活、热加载和崩溃恢复。目录拒绝同一版本既可安装又撤回；控制台对已安装撤回版本显示固定风险原因并引导升级或卸载，密钥泄露仍由信任库 `revoked` 做强制隔离。控制器为活动路由保存完整插件清单快照，部署自检可识别服务数量相同但版本、入口、方法、参数等发生变化的磁盘漂移；它不会自动加载人工目录变化。管理员显式完整重扫时也先验签、核对当前来源至少覆盖每条候选签名路由、拒绝隐式删除已活动签名插件或破坏现有公共 API，并逐组件启动候选宿主，全部成功后才替换活动路由。本地签名包选择同样不会直接安装：只读预检先完成验签、兼容/防降级、联合路由、活动路由一致性、来源授权覆盖和候选宿主 Health；同 ID 候选还以规范方法名与 alias 同为公共 route 的规则比较输入和响应契约，删除 route/字段、改变类型或增加必填输入会阻断，安全新增与原生绑定复核只展示聚合计数。确认标识绑定规范候选载荷、目标插件当前签名状态和 Desktop 版本，安装时重新打开文件并在激活前再次核对基线、API 兼容性与授权覆盖，且预览不返回本机路径、签名 keyId、来源或路由明细。已接受签名契约还原子保存为有界本地基线：退出期间人工换入的同 ID 破坏性包在下次路由加载前隔离，暂时缺失以显式墓碑保留，无关安装、项目导入或重扫不能顺带清除。安装、回退、卸载、项目导入和重扫在自身持久提交点前先写下一契约集；崩溃启动先恢复目录事务，再精确匹配旧/下一集合以撤销或完成，歧义失败关闭。准备记录写入失败阻止插件提交，提交后的基线收尾失败保留恢复记录并以稳定计数提示，不伪装成插件回滚；对应显式卸载成功才退休墓碑。基线不含路径或调用数据。控制台的仓库浏览也不会安装：它从签名目录自动发现未安装插件，连同已安装版本、最高兼容版本、仅支持其他 Desktop 的新版本和撤回状态一起展示；同名本地映射或异常目标目录作为逐插件阻塞项，不隐藏其他仓库条目。扫描会在隔离无效映射前保留规范化磁盘身份，所以损坏映射以及只存在 ASCII 大小写差异的冲突也不能产生安装计划；检查和最终激活使用同一冲突来源。精确查询已安装插件时还可选择最多 16 个最近的兼容、未撤回仓库版本做受控回退；每个目标独立绑定确认标识并要求风险确认，最终仍走二次验签、公共 API 兼容门禁、来源授权覆盖、宿主预检和可恢复原子激活，而本地包和项目导入继续禁止降级。用户确认精确兼容版本后才进入安装流程。仓库确认标识绑定完整签名目录条目、目录签名 keyId、当前 Desktop 版本和目标插件签名文件状态；安装命令重新获取目录并在下载前复算，下载完成进入原子激活时再次核对目标插件基线，任一漂移都要求重新检查。旧插件元数据可用于迁移诊断，但缺少兼容范围时不会进入运行路由或正式发布目录。签名插件还可由控制台显式卸载；卸载预检重新验签并展示精确版本、服务和方法计数，确认标识绑定完整签名载荷、身份与 Desktop 版本，安装锁内、维护排空后和目录事务暂存后三次复核，最后一次直接针对实际待删除字节；任一漂移先恢复原目录并要求重新确认。卸载与本地映射删除都只排空目标插件，并通过可恢复事务一起切换目录和路由，避免直接删除造成崩溃后半完成状态。项目包导入还复用普通配置导入的同一差异摘要，并在预览/确认两阶段比较已安装签名 API，使实施人员同步看到配置、组件动作、API 新增和原生复核计数，不再只看到一个“配置更新”布尔值。

管理员完整重扫也不再把按钮点击直接等同于全局路由替换。预检先展示候选插件、本地映射、服务、方法、新增、路由变化、未进入候选清单的映射和隔离项聚合影响，并把当前活动契约、候选完整字节、磁盘身份、隔离结果和 Desktop 版本绑定为确认标识。确认命令在安装锁内、宿主复检后和全局维护排空后三次核对；路由替换后再次复验实际目录，漂移会恢复扫描前完整路由。业务页面没有重扫预检或提交权限。

面向整项目迁移的 `.ssdev-project` 使用独立 `project-bundle` 组织旁签绑定整个交付容器；正式客户端缺少旁签或遇到重新封包、错用途、吊销密钥时会在预检前失败。容器创建、最终写入与读取使用同一组件声明语义：Windows 大小写不敏感身份唯一，签名插件必须声明有效 SemVer，本地映射不得声明发布版本；最终写入重新规范排序并拒绝复制的已准备身份，相同集合不会因任务间重排产生不同包。组织签名通过后，再在只读阶段以包内精确能力集合联合验证来源授权覆盖、全部组件、路由和宿主，并展示配置更新、组件新增/升级/修复/替换及目标机包外能力。包外能力保持可见但阻断导入，必须通过已有逐项卸载/删除事务处理或纳入重新生成的项目包；客户端既不自动删除，也不允许它们静默进入新项目。确认标识绑定项目包、Desktop 版本及目标机配置和全部组件内容；确认命令在项目事务创建前再次复算目标机摘要并核对活动路由，组件激活后核对项目包精确清单，配置与路由切换后又在持久提交点前重算目标配置和完整能力内容。任一阶段出现新增、缺失、隔离、内容或路由漂移都会恢复旧配置、旧路由和组件并要求重新预检；全部复核通过后才写项目级提交点，提交前失败或崩溃整体回滚，提交后整体完成，不再保留逐组件成功导致的混合版本状态。
