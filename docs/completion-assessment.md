# SSDEV Desktop Next 完成度评估

评估日期：2026-08-29

## 结论

项目已经具备进入“真实业务验收”的工程条件，但尚不能宣布生产切换完成。代码、自动测试和合成安装包门禁覆盖了 Tauri 桌面壳、无 HTTP 的 Web Bridge、x86/x64 隔离插件宿主、DLL/COM/OCX/EXE/BAT、签名插件生命周期、最小 Rust DLL 插件脚手架、用公开测试密钥制作双架构签名包并经过正式发布集合物化、由生产黄金矩阵包装器分别实际调用 x86/x64 宿主及核对 schema 2 证据、无密钥源检查、相对上一签名包及正式目录内多版本的 Web API 兼容门禁、工作台与发布工具共用的类型化 Web 客户端生成、无需桌面或硬件的严格前端 fixture invoker、从结构完整黄金矩阵生成同路由 Web fixture、把单插件客户端与 fixture 原子绑定为带来源摘要清单且可在业务 CI 重复验证的 Web 接入包、默认 CI 生成的可重复 Web Bridge SDK `.tgz` 与锁定源码摘要清单及离线 ESM/TypeScript 消费者冒烟、一个或多个精确 Web kit 与同一 SDK 制品的离线严格联合编译、插件身份/公开路由冲突检查和全路由组合冒烟、业务 HAR 有效/跳过请求分离统计及不完整扫描阻断、单包及多包发布集合与黄金矩阵联合离线检查、批准发布集合的一次性验收目录生成、现场插件目录到硬件证据的逐包摘要绑定、硬件矩阵与安装后插件信任库及 x86/x64 宿主的逐字节身份对账，以及生产策略对试点材料、指定上一生产版本、候选与上一版本 Windows 产物清单、批准插件集合/信任库/矩阵和八类迁移资产最低覆盖的精确约束、应用更新、配置迁移、SSO、多窗口、截图、诊断和供应链证据。剩余风险主要不是继续猜测实现，而是缺少生产插件、真实硬件、业务 HAR、生产签名体系和上一生产安装包等外部材料。

试点材料现在可以用独立只读工具建立脱敏移交基线：十类核心材料必须实际提供，旧快捷键、受控进程和外部本机 HTTP 调用方三类条件材料必须提供或引用明确的不适用审批；schema 2 manifest 还把正式迁移审计的配置、插件、快捷键、业务前端、HAR 和签名策略角色精确绑定到对应类别。报告绑定每类内容、角色摘要与总集合摘要且不保存路径、项目标签或审批原文。接收方可以严格加载报告并对收到的同一 manifest 和材料目录重算逐字段身份，阻断报告、清单、角色或文件被替换。该报告始终声明后续验证仍然必需，因此不会把输入收齐替代迁移审计、黄金矩阵、Windows 实机或生产 Go/No-Go。

## 分层完成度

正式迁移审计现在只从已复验试点 manifest 派生输入和候选安装包的 active 签名来源策略，禁止混入手工路径，并在执行前后复验整个材料集合。生产策略也由 clean 源码、同一试点三件套、候选/上一生产 bundle、批准插件集合和组织 QA 证据信任库自动生成；人员只决定证据时效、覆盖下限和四个职责签名人。schema 7 策略固定 QA 与最终审批信任库，并由现有最终审批职责使用独立 `cutover-policy` 域签名；schema 3 GO 决策固定策略封套和实际两份信任库，同名 keyId 的替代公钥库不能通过判定或签发。迁移 schema 3 与生产策略共同绑定试点材料集合，迁移与 Windows 包 schema 7 及生产策略继续绑定同一来源策略摘要；Windows 包还必须绑定独立的指定上一版本回装启动、应用状态保留结果，以及同版本、近期且包含真实业务页握手的深度部署记录。换材料、换策略、换策略封套、换信任根、复制错误、用其他低版本替代真实升级、只完成候选升级、只完成回装启动或只启动控制台都会失败关闭。

## 原平台能力覆盖判断

- 桌面壳主能力已覆盖：环境配置与迁移、托盘、单实例、多窗口、缩放/查找、开机启动、SSO、截图、缓存清理和诊断。不可恢复的 WebView 站点数据清理不再从托盘单击执行：本地控制台先显示当前配置来源、业务窗口和悬浮页面聚合影响，确认标识绑定规范来源、窗口集合与 Desktop 版本，复核通过后才向共享 WebView 配置文件提交清理并关闭受影响页面；Cookie、登录状态、缓存和本地存储的清理请求为异步提交，提示不会谎报同步擦除，也明确不回退设备操作或服务端业务数据。安全的全窗口刷新则逐项尝试并返回请求、成功和失败聚合计数，不会因为一个 WebView 失败把已经刷新过的其他窗口误报为整体失败；无窗口明确为无操作，托盘部分失败会打开本地控制台，刷新成功后的页面仍进入业务 IPC 就绪监督。Release 启动失败不依赖黑色终端窗口：初始化阶段失败显示稳定错误码、处理建议和日志目录；控制 WebView 创建后 15 秒没有到达 Rust IPC 时也会从原生层提示，就绪/超时由单一状态机裁决，后续成功启动会在最近故障文件中写入恢复时间和应用版本，正常控制台可直接打开日志目录。桌面、controller、插件宿主与原生适配器的生产 Rust 源码禁止直接 `unwrap`、`expect`、`panic` 和 `unreachable`；宿主缺失、深度自检失败、项目状态暂存异常、仓库回退元数据缺失和矩阵命名耗尽都进入显式错误或失败检查项，不终止客户端。普通配置文件导入与项目包一致采用先预检后确认：用户先核对入口、来源、环境、进程、快捷键和桌面行为摘要，确认时重新绑定候选配置和当前已保存状态，避免检查后文件或本机状态变化造成静默覆盖。普通保存和导入一旦改变业务来源集合，还会以控制器当前活动插件快照检查现有签名路由，候选来源让任一路由完全失去授权时在写配置前失败；非来源设置不受影响，需要配置与插件一起切换时使用项目包。部署快速检查不主动创建宿主，也不再被首页误报为“可以交付”；报告以独立 `deliveryReady` 绑定 Windows 深度检查，快速通过只提示继续验证宿主，非 Windows 明确标为开发预览。Windows 手动深度自检及现场记录导出会让当前插件在实际 x86/x64 隔离候选宿主中重新完成原生加载与 Health 预检，失败阻塞交付并显示首个阻塞插件、实际架构、稳定诊断码及针对性处理建议。本地安全页还按插件和架构区分按需待机、运行中、启动退避与等待重试，保留累计失败和稳定诊断码但不暴露路径、厂商错误或调用数据。Health 失败保留组件缺失、路径越界、DLL、COM/OCX、进程入口和不支持声明等固定类别，controller 只接受白名单并由控制台给出对应处理建议；插件安装、仓库更新、本地映射激活和深度自检都只消费结构化失败结果，原生文本不会被格式化到本地提示。失败宿主可由本地操作员按插件和架构立即恢复，跳过一次短退避并重做 Health，但不调用 DLL/COM 业务方法或启动 EXE/BAT，也不绕过维护与退出边界。导出记录有界、脱敏、不覆盖并明确为未签名现场记录，不替代生产切换签名证据。
- 高频持久操作已经区分“主操作提交结果”和“提交后页面刷新结果”。配置、项目、插件、宿主恢复和深度自检成功后，即使某类只读状态暂时无法读取，也不会被误报为操作失败；页面保留成功事实、逐字段标记待刷新状态，并暂停依赖旧快照的重复提交、业务启动和交付判断，直到人工刷新完成。每类读取有独立 15 秒上限且并发刷新不会互相覆盖缺失状态，底层读取错误不进入页面。
- 项目配置表单具有独立的确定性已保存基线，能够识别嵌套来源、环境顺序及未知兼容字段变化而不受对象键顺序影响。草稿会在配置页和首页待处理区明确显示，并暂停业务启动、有效配置/项目导出、项目包预检、插件/本地映射变更和部署自检；实施人员可以保存或有界重新读取后放弃，关闭控制窗口也有未保存保护。配置导入预检不会立即丢弃草稿，确认成功才采用后端有效快照；项目包预检后产生的新草稿仍需在导入前单独确认覆盖。
- 原生映射工作台的未保存状态也进入统一项目交付草稿门禁。草稿不会贡献“可以交付”结论，项目包生成/预检、签名插件集合变更、应用更新和深度自检都要求先保存或放弃映射；命令入口与界面同时防护，项目导入覆盖仍需明确确认且失败保留草稿。工作台自身也不会把磁盘中的旧映射冒充为当前表单：当前映射未保存时暂停现场调用、用例保存/回归、TypeScript、迁移包和发布源，并立即隐藏旧调用结果；其他无关已保存映射仍可独立导出。现有业务窗口维护、诊断和仅完成 Health 的宿主恢复继续可用，避免为了保护草稿扩大无关阻断范围。
- 映射保存、导入和删除已经区分“原生能力提交”与“工作台清单复核”。提交成功会立即触发全局状态刷新；后续有界清单读取失败只显示“操作已完成、映射待复核”，不会诱导重复保存或删除。此时首页、部署结论和所有依赖映射清单的项目操作统一暂停，但原生映射页保留专用重试；复核成功后使用磁盘规范化定义恢复编辑器和草稿基线。
- 已保存映射的 ID 作为稳定路由身份在编辑器中固定；新建草稿若命中现有 ID，会明确提示整份原生组件、服务、方法和调试用例将被替换。保存请求把清单观察到的目标存在状态绑定到 Rust 命令，后端在安装锁内复核后才准备候选目录，确认后发生的外部创建、移除或异常目录替换都会要求重新读取，不会依据过期页面静默覆盖。
- 本地映射删除先由 Rust 只读复核实际磁盘和活动路由，控制台在一次确认中展示服务、方法、回归用例和未保存草稿影响。删除计划绑定规范映射内容、身份与 Desktop 版本，并在安装锁内、目标维护排空后及目录原子暂存后依次复核；最后一次针对实际待删除字节，不一致先恢复目录，确认后发生的内容替换、隔离或路由漂移不会被旧页面继续删除。
- WebPlus 主能力已覆盖：业务请求兼容、x86/x64 路由、DLL、COM/OCX、EXE/BAT、超时、背压、崩溃恢复和隔离宿主。通用 DLL 的 12 参数机器字 ABI、调用约定、参数方向/类型、输出缓冲区和返回类型限制，以及 COM Automation 的 BSTR、布尔、32 位有/无符号整数、双精度浮点与对应 BYREF 输出限制，均已上移为跨平台共享清单规则，插件准备、签名输入、桌面加载与 Windows 宿主不会各自接受不同声明；工作台只展示实际支持的常用 DLL 类型，并能可视化配置 COM 调用后读取属性。`ResData.ReturnValue` 被定义为稳定的原生返回字段；配置加载会拒绝同名输出参数、同名 COM 属性以及属性与输出参数重名，原生运行时合并结果时仍逐字段拒绝覆盖，避免调用成功却静默改变返回语义。签名插件和本地映射的 EXE/BAT 入口会把已验证 SHA-256 带入原生预检，Windows 宿主持有不可写/不可删除句柄，并在每次创建子进程前重新散列，避免宿主存活期间按原路径换入未批准内容。
- 旧版任意 Shell 进程和 `eval` 快捷键没有原样迁移，而是替换为签名进程策略和声明式动作。这属于有意的安全收敛，不应作为缺失能力重新开放。
- 旧本机 HTTP 端口 `7711`、`45121` 不再是 Tauri 内部通信依赖。是否仍需独立兼容适配器，必须由代表性 HAR 和外部调用方清单决定。
- Win10/11 x64 与 x86 是正式目标；当前 Tauri/Rust/WebView2 组合不把 Win7 列为正式支持范围。
- 业务窗口具备独立页面就绪状态机：每次返回业务来源后 30 秒内必须到达 Rust IPC，超时通过原生对话框、首页、部署检查和脱敏诊断反馈；SSO 导航不误报。首页可以只认领并重新加载点击时仍处于超时的窗口，已就绪、登录跳转中或自行恢复的窗口不受影响；加载失败恢复原超时状态，成功后重新进入同一有界监督。深度交付检查要求真实页面握手，快速日常检查在未启动窗口时保持非阻断。

## DLL 映射可视化

内置控制台既展示通过当前信任库验签并重新发现成功的发布插件，也提供可写的本地原生映射工作台。发布插件提供以下只读拓扑：

`插件 ID/版本 → serviceId → x86/x64 与 mainType → mainClass（DLL 相对路径或 COM ProgID）→ 请求方法名 → 原生导出/成员名`

同时展示调用约定、字符集、服务/方法超时、缓存策略、依赖数、参数数和返回类型。绝对插件根目录不进入发布映射数据；隔离插件不进入可调用拓扑。

本地工作台可以选择 DLL/EXE/BAT、只读识别 PE 架构和命名导出，或按 x86/x64 注册视图搜索 COM/OCX 后选择 ProgID/CLSID；管理员可编辑服务、方法、参数、返回值、依赖、字符集和调用约定。保存时组件被复制到固定本地映射根目录，在正确位数的隔离宿主中预检，然后以持久事务原子热加载；普通失败和进程崩溃都会恢复旧目录和路由。未签名 `.ssdev-mapping` 不再因文件选择就加载原生代码：只读结构预检先展示安装/替换、服务、架构、类型、方法和用例范围，明确确认后重新绑定包摘要、Desktop 版本和目标映射状态，复核通过才执行宿主预检与按插件原子激活。编辑器会标记未保存草稿，并在新建、切换、导入或关闭前防止静默覆盖；项目包成功切换后才重载磁盘映射，失败仍保留草稿。独立保存调试用例不会掩盖其他未保存 ABI 字段。工作台还提供同路由现场调用、耗时与结构化结果查看，可保存有界的合成输入并顺序回归 `ResCode`、`ReturnValue` 和关键输出字段，以及导出类型化 Web Bridge 客户端和包含组件/用例的 `.ssdev-mapping`。生成客户端在常见场景直接使用公开 alias/方法名，无输入调用不要求空对象；只在跨服务重名或标识清洗冲突时增加服务前缀或序号，底层路由仍固定为原声明；声明的 COM 属性会进入结果类型，无法从配置证明的属性类型保持为 `JsonValue`。稳定映射可导出仅含 API 与引用组件的最小发布源，并在其目录外生成仍为草稿的正式矩阵种子；签名工具会强校验路由、完整输入和全方法覆盖，正式运行器即使遇到被误改为非草稿的遗留占位符或未解除的精确响应复核标记，也会在启动宿主前失败，同时避免现场用例进入签名插件。COM 注册发现只读元数据且不实例化未知组件；复杂结构体、回调或厂商自定义 ABI 仍需要专用 Rust 适配器。

## 更新机制

### 应用本体

已经实现 HTTPS 更新清单、内置公钥、Tauri Minisign 验签、流式大小上限、崩溃残留更新文件的定向清理、安装前停止插件调用、失败恢复准入并保留原业务窗口，以及成功交接后的进程重启。更新临时根拒绝符号链接，清理只匹配客户端固定前缀的普通文件，不触碰同目录其他内容。运行时检查、下载、中断、HTTP 状态与安装器交接错误均映射为稳定错误码和处理方向，不把私有端点、下载 URL、临时路径或底层原文返回控制台或写入日志。安装交接失败后控制台会退出安装中状态、作废已消费的计划并引导重新检查，不会继续展示一个可重复提交的失效确认。检查和安装阶段都会以目标 Desktop SemVer 重新验证当前签名插件与本地映射的完整集合，在下载前阻止会使现有能力被隔离的应用升级。确认标识绑定精确 pending 更新元数据、Minisign 签名、当前全部签名插件载荷及本地映射确定性内容；安装前和包验签后分别复核，另一轮检查替换 pending 或下载期间任一能力发生变化都会要求重新确认。正式验收仍需生产更新端点、真实签名密钥、代码签名证书以及从上一生产版本执行升级和失败回滚。

### 插件

正式目录生成阶段会按 SemVer 重新验签并比较规格内同 ID 的相邻可安装版本，破坏公共 Web Bridge 契约时在目录落盘前失败；成功报告给出实际比较数且不包含本地路径。目录只包含一个版本时不会冒充历史兼容证明，仍要求用上一批准签名包执行独立 `api-check`。

已经实现短期签名目录、独立目录签名用途、精确大小/SHA-256、插件包二次验签、显式 Desktop SemVer 兼容范围、插件 SemVer 防降级、精确版本撤回、x86/x64 宿主预检、按插件维护、原子激活、热加载和崩溃恢复。目录拒绝同一版本既可安装又撤回；控制台对已安装撤回版本显示固定风险原因并引导升级或卸载，密钥泄露仍由信任库 `revoked` 做强制隔离。控制器为活动路由保存完整插件清单快照，部署自检可识别服务数量相同但版本、入口、方法、参数等发生变化的磁盘漂移；它不会自动加载人工目录变化。管理员显式完整重扫时也先验签、核对当前来源至少覆盖每条候选签名路由、拒绝隐式删除已活动签名插件或破坏现有公共 API，并逐组件启动候选宿主，全部成功后才替换活动路由。本地签名包选择同样不会直接安装：只读预检先完成验签、兼容/防降级、联合路由、活动路由一致性、来源授权覆盖和候选宿主 Health；同 ID 候选还以规范方法名与 alias 同为公共 route 的规则比较输入和响应契约，删除 route/字段、改变类型或增加必填输入会阻断，安全新增与原生绑定复核只展示聚合计数。确认标识绑定规范候选载荷、目标插件当前签名状态和 Desktop 版本，安装时重新打开文件并在激活前再次核对基线、API 兼容性与授权覆盖，且预览不返回本机路径、签名 keyId、来源或路由明细。已接受签名契约还原子保存为有界本地基线：退出期间人工换入的同 ID 破坏性包在下次路由加载前隔离，暂时缺失以显式墓碑保留，无关安装、项目导入或重扫不能顺带清除。安装、回退、卸载、项目导入和重扫在自身持久提交点前先写下一契约集；崩溃启动先恢复目录事务，再精确匹配旧/下一集合以撤销或完成，歧义失败关闭。准备记录写入失败阻止插件提交，提交后的基线收尾失败保留恢复记录并以稳定计数提示，不伪装成插件回滚；对应显式卸载成功才退休墓碑。基线不含路径或调用数据。控制台的仓库浏览也不会安装：它从签名目录自动发现未安装插件，连同已安装版本、最高兼容版本、仅支持其他 Desktop 的新版本和撤回状态一起展示；同名本地映射或异常目标目录作为逐插件阻塞项，不隐藏其他仓库条目。扫描会在隔离无效映射前保留规范化磁盘身份，所以损坏映射以及只存在 ASCII 大小写差异的冲突也不能产生安装计划；检查和最终激活使用同一冲突来源。精确查询已安装插件时还可选择最多 16 个最近的兼容、未撤回仓库版本做受控回退；每个目标独立绑定确认标识并要求风险确认，最终仍走二次验签、公共 API 兼容门禁、来源授权覆盖、宿主预检和可恢复原子激活，而本地包和项目导入继续禁止降级。用户确认精确兼容版本后才进入安装流程。仓库确认标识绑定完整签名目录条目、目录签名 keyId、当前 Desktop 版本和目标插件签名文件状态；安装命令重新获取目录并在下载前复算，下载完成进入原子激活时再次核对目标插件基线，任一漂移都要求重新检查。旧插件元数据可用于迁移诊断，但缺少兼容范围时不会进入运行路由或正式发布目录。签名插件还可由控制台显式卸载；卸载预检重新验签并展示精确版本、服务和方法计数，确认标识绑定完整签名载荷、身份与 Desktop 版本，安装锁内、维护排空后和目录事务暂存后三次复核，最后一次直接针对实际待删除字节；任一漂移先恢复原目录并要求重新确认。卸载与本地映射删除都只排空目标插件，并通过可恢复事务一起切换目录和路由，避免直接删除造成崩溃后半完成状态。项目包导入还复用普通配置导入的同一差异摘要，并在预览/确认两阶段比较已安装签名 API，使实施人员同步看到配置、组件动作、API 新增和原生复核计数，不再只看到一个“配置更新”布尔值。

管理员完整重扫也不再把按钮点击直接等同于全局路由替换。预检先展示候选插件、本地映射、服务、方法、新增、路由变化、未进入候选清单的映射和隔离项聚合影响，并把当前活动契约、候选完整字节、磁盘身份、隔离结果和 Desktop 版本绑定为确认标识。确认命令在安装锁内、宿主复检后和全局维护排空后三次核对；路由替换后再次复验实际目录，漂移会恢复扫描前完整路由。业务页面没有重扫预检或提交权限。

面向整项目迁移的 `.ssdev-project` 使用独立 `project-bundle` 组织旁签绑定整个交付容器；正式客户端缺少旁签或遇到重新封包、错用途、吊销密钥时会在预检前失败。组织签名通过后，再在只读阶段联合验证来源授权覆盖、全部组件、路由和宿主，并展示配置更新、组件新增/升级/修复/替换及本机额外能力保留的变更计划。确认标识绑定项目包、Desktop 版本及目标机配置和全部组件内容，状态变化必须重新预检；复核通过后才以项目级持久提交点一起切换签名插件、本地映射、控制器路由和配置，提交前失败或崩溃整体回滚，提交后整体完成，不再保留逐组件成功导致的混合版本状态。

## 实际测试准入清单

1. 提供一套已脱敏的生产插件目录、代表性请求/响应和预期结果，生成覆盖所有 service/method 的黄金矩阵。
2. 在 Windows x64 真实设备上同时测试 32 位 DLL、已注册 OCX、硬件驱动和院内证书。
3. 提供业务前端产物和代表性账号 HAR，确认不再依赖 `7711`/`45121`；若仍有外部调用，再单独评审兼容适配器。
4. 配置非生产签名插件仓库和应用更新端点，先演练查询、指定版本安装、失败回滚与应用升级。
5. 生产发布前接入 KMS/HSM、公钥信任库、Windows 代码签名证书和真实上一版本安装包，完成灰度与回退演练。
